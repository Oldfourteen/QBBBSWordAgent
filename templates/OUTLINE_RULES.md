# QBWordAgent 唯一大纲设计规范

每次T1只读取本文件、同目录outline.md骨架和本次用户材料。不得读取其他任务的大纲、正文、回执或历史生成脚本来决定章节。历史错误约束可用于格式检查，不能作为本次内容或事实来源。

## 固定方法

1. 从本次材料明确实际项目主题、要解决的问题、已有信息及缺少的证据；不得虚构实践过程或结果。
2. 使用outline.md的“背景与目标→需求与方案→实现与验证→总结与改进”骨架；按本次主题改写标题，保留问题、方法、验证和反思的覆盖。纯分析主题使用分析步骤及比较依据代替虚构开发经历。
3. 每个章节用列表说明拟写内容及其材料依据；缺少实际数据时明确准备讨论的范围与局限。
4. 大纲只写标题正文：一个#报告主题，2至8个##一级章节，总共2至12个###二级标题。二级标题必须归属前一个一级章节。标题唯一、层级清晰，不预写页码或序号。
5. 检查主题一致、内容不重叠、前后逻辑连贯、标题层级完整、无占位符、无作者身份信息。运行save-outline进行程序自检后停在闸门1。

## 本次输入与锁定

- 先由用户确认学年和学期，再设计大纲。学年建议按本年Y提供Y-1至Y、Y至Y+1，允许用户提供其他连续学年。
- 题目在闸门1通过后另行确认，不要求为了显示题目重新设计已批准大纲。
- 只使用本任务目录的outline.draft.md提交；闸门1批准后，正文标题必须与该大纲一一对应。
- 主题、篇幅或材料变化时按workflow回退；不能借用历史任务绕过确认。
